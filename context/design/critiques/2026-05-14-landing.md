## #7 Visual — Maren-equivalent (PagePerfect: Visual designer, seat #7)

The landing reads as one editorial voice. The "signature move" — oversized display ink set against generous cream — is used **once per section**, which is the correct discipline. `Hero` and `FinalCTA` book-end the page with the same compositional weight; `WhyDifferent` carries the editorial spine in the middle. Red `#FF3333` is reserved for primary CTAs, the Publisher tier badge in `PricingPreview`, and the step-numeral accent in `Steps` — no decorative red, no red on body copy. Sharp geometry holds throughout (no `rounded-*` leakage observed).

Where it weakens: the micro-labels (Hero's `[ Markdown → KDP ]`, SocialProof's metadata, Engineering's category labels) are pushed so far back in the value scale that they read as decoration, not metadata. That tips the page from "confident" to "ornamental" in those spots. The fix is not to make them louder — it's to bring them up to the `#555555` floor so they read as labels, which is what they are.

Findings:
- P1 — `Hero.tsx:18` — micro-label `text-[#111111]/25` reads as decoration not type — raise to `text-[#555555]`
- P2 — `Comparison.tsx:48–95` — Times New Roman / Georgia inline `style` props are intentional mockup props; defensible but worth a comment explaining intent so they don't get "fixed" later

## #15 Systems — Staff engineer (seat #15)

The kit *does* have tokens — `globals.css` defines `--ease-pp`, `--t-fast`, `--t-medium`, plus Tailwind's palette is fully wired in `DESIGN.md`. What's missing is a **text-color token system** to replace ad-hoc opacity stops. Today there are at least six different ink values in active use across the landing alone: `text-[#111111]` (full), `/60`, `/50`, `/45`, `/35`, `/30`, `/25`, plus `text-[#333333]` and `text-black/45`. That is drift, not design.

The DESIGN.md principle #5 floor — `#555555` for labels, `#333333` for body — is correct, but the codebase has no token expressing it, so it isn't enforced. Right move: add `text-ink`, `text-ink-body`, `text-ink-label`, `text-ink-mute` Tailwind tokens mapping to `#111111` / `#333333` / `#555555` / `#777777`, then ban raw `text-[#111111]/NN` for functional text via a follow-up `design-token` pass.

Findings:
- P1 — Repo-wide — define ink tokens in `tailwind.config.ts` mapping to DESIGN.md #5 floor; route through `design-token` skill
- P1 — `Comparison.tsx:62,82` — inline `fontFamily` strings should at least live in a `mockupStyles` const at the top of the file (currently they're duplicated and grep-hostile)
- P2 — `Hero.tsx:23` / `SocialProof.tsx:18,24` / `Engineering.tsx:71,82` / `PricingPreview.tsx:138` — replace `text-[#111111]/NN` with semantic token once tokens exist

## Motion — contract check (no dedicated council seat — see Gaps)

`Reveal.tsx:13–23` reads `prefers-reduced-motion: reduce` and returns a plain `<div>` with content immediately visible — no opacity tween, no transform, no observer overhead. That is the correct contract. Easing is `cubic-bezier(0.25, 0.4, 0.25, 1)` / 700ms, matching `--ease-pp`. No `@keyframes` on body type. No parallax. No marquees. `RevealGroup` staggers children with the same easing.

There is no motion-related blocker. There is a **council gap**: the Standing Council in `memory/PROCESS.md` does not include a motion seat (the Design Council sub-council mentions "Motion (Idris)" but Idris is an AG-residual name and no PagePerfect motion specialist is on the seat list). For now, motion is reviewed through the Accessibility lens via the reduced-motion clause; that's adequate for the landing but won't scale to richer marketing surfaces. Promotion to a council follow-up.

Findings:
- P2 — `memory/PROCESS.md` — add a motion seat to the Standing Council (or formally name the Design Council motion sub-council member). Promote to a separate `pp-handover` follow-up.

## #13 UX — UX writer (seat #13)

The reader's task is legible: read the hero promise → see the .docx-vs-.pdf comparison → scan the three steps → understand the tier story → click a primary CTA. Each section earns one "look" and gets out of the way. `Hero` is unambiguous about what the product does (`Markdown → KDP`). `Comparison` is the strongest narrative beat — showing the failure mode of Word is more persuasive than describing it.

Where it stumbles: `PricingPreview.tsx:138` — "Compare all plans & FAQ" is the secondary path for anyone who isn't ready to commit at the tier preview, and it's set in `text-[#111111]/35`. That's not just an a11y miss (covered below); it's a UX failure — the page is hiding the answer to the most common pre-purchase question. The link should look like a link.

Findings:
- P0 — `PricingPreview.tsx:138` — secondary path to FAQ is visually buried; lift to underlined `text-[#111111]` (the link semantics, not just the color, are missing)
- P2 — `Hero.tsx:35–39` — primary CTA has no secondary action ("See sample PDF" or similar). Not a blocker; flag for conversion-skill review.

## #17 Performance — Performance engineer (seat #17)

Budget is healthy. No WebGL. No Vanta. No raster hero. The landing uses three font families (Inter Tight / Source Serif 4 / IBM Plex Mono) — within budget for an editorial site, and they're configured at the layout level so they cache across routes. IntersectionObserver via `Reveal` is `O(1)` per element with sensible thresholds. No `@keyframes` driving expensive transforms (filter, drop-shadow). `Comparison` uses inline SVG-equivalent text rendering rather than rasters.

No measurements taken in this critique — recommend the `audit` skill (per the critique skill's own companion list) to spot-check Lighthouse and CLS, since the `Reveal` opacity-and-translate transitions can shift layout if `will-change` isn't set. Not flagged as a finding without measurement.

Findings:
- P2 — Run `audit` skill against `/` for Lighthouse + CLS spot-check on `Reveal` transitions. No live finding without numbers.

## #8 Accessibility (VETO) — Accessibility specialist (seat #8)

**Four AA failures, one of them an interactive element. This blocks ship.**

DESIGN.md principle #5 sets the canonical floor: `#555555` for labels, `#333333` for body. The landing has multiple text colors below that floor, set via `text-[#111111]/NN` opacity stops on the cream background:

- `text-[#111111]/25` on `#FDFCF8` ≈ **1.5:1** contrast — fails AA (needs 4.5:1 for body, 3:1 for large text)
- `text-[#111111]/30` ≈ ~1.7:1 — fails
- `text-[#111111]/35` ≈ ~1.9:1 — fails
- `text-[#111111]/45–/50` ≈ ~2.3–2.6:1 — fails for body; borderline for large text only

The interactive-link miss (P0) is the most serious — links must hit AA *and* be visibly distinct from surrounding text. Today the link is both below contrast *and* underline-less, so it doesn't read as a link by either signal.

Skip-link is present in `(site)/layout.tsx`. Focus visibility was not audited in this static read — needs runtime check (browser tab-through). Semantic structure (`<h1>` / `<h2>` / `<main id="main">`) is correct. Reduced-motion is honoured by `Reveal`.

Findings (any P0 here blocks ship):
- **P0** — `PricingPreview.tsx:138` — "Compare all plans & FAQ" link at `text-[#111111]/35` is an interactive element below AA. Raise to `text-[#111111]` and add `underline underline-offset-4`. **Blocking.**
- **P0** — `Hero.tsx:18` — micro-label `[ Markdown → KDP ]` at `text-[#111111]/25` fails AA; even as decorative label this violates DESIGN.md #5. Raise to `text-[#555555]` (or `#555` token). **Blocking.**
- **P0** — `SocialProof.tsx:18` — label keys (`Compile target`, `Trim sizes`, etc.) at `text-[#111111]/25` carry semantic meaning and fail AA. Raise to `#555555`. **Blocking.**
- **P0** — `Engineering.tsx:71` — category labels (`COMPILE`, `TYPOGRAPHY`, `PRINT-READY`, `WORKFLOW`) at `text-[#111111]/30` fail AA and are above-fold metadata. Raise to `#555555`. **Blocking.**
- P1 — `Hero.tsx:23` — body line `text-[#111111]/50` is borderline; on the cream specimen this clears 3:1 (large-text AA) but misses 4.5:1 (body AA). It's set in display-scale type so large-text AA *does* apply — keep, but verify the exact pixel size at the smallest viewport.
- P1 — `Comparison.tsx:62,82,88,95` — `text-black/45` and `text-black/50` are inside mockup blocks (the "bad Word output" sample). Those are *intentionally* poor typography — but the literal characters are still in the DOM and read by screen readers. Wrap mockup blocks in `aria-hidden="true"` so AT users aren't fed broken copy that's there as a visual prop.
- P2 — `(site)/layout.tsx` — verify focus-ring visibility on Nav links and Footer links under runtime. Static read can't confirm.

## Sign-off

- **Can this ship as-is?** **No.** Four P0 accessibility findings block ship under PagePerfect's #8 veto.
- **What blocks:** the four P0 contrast failures listed above. The interactive link in `PricingPreview` is the most serious — links must hit AA contrast *and* be visibly distinct.
- **Recommended remediation order:** (1) fix the four P0s in a single `design-component` pass (≈30 minutes — they're all `text-[#111111]/NN` → `text-[#555555]` swaps plus an `underline underline-offset-4` on the FAQ link); (2) run `design-token` to add the ink token set; (3) sweep the codebase with the new tokens to retire ad-hoc opacity stops; (4) run `audit` for runtime Lighthouse / focus / CLS confirmation.
- **What's exemplary, keep doing it:** the discipline of using full `#111111` ink for headlines and body in `Hero`, `WhyDifferent`, and `FinalCTA`; the restraint on `#FF3333` (CTAs and one badge only); the sharp geometry; the typography hierarchy in `Steps`; the correct reduced-motion contract in `Reveal`; the editorial restraint of one signature move per section.
